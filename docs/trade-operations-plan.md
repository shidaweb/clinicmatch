# 運営のフォローを途切れさせないための設計案

作成：2026年9月18日  
現状の根拠：[取引フロー・メール監査](./trade-flow-audit-2026-09-18.md)

## 1. まず決めること

**全ての進行中案件に、運営担当者・次に動く人・具体的な対応・期限を一組で持たせます。** 「返信待ち」でも運営の責任は残ります。相手の返答期限と、運営が再確認する期限を分けて管理します。

公開状態、商談の段階、運営タスクの状態、メールの配信状態は別です。「公開済み」「メール送信済み」だけで対応完了にしません。

本書の期限は提案です。現在の自動処理や利用者への約束ではありません。運営時間の仮案を平日9:00〜18:00 JST、土日祝は翌営業日扱いとし、人員・休日対応を決めてから確定します。緊急案件には個別の期限を設定します。

## 2. 役割と責任

| 役割 | 責任 | 不在・期限超過時 |
|---|---|---|
| 受付当番 | 新着・通知失敗・未割当を確認し、担当を一人決める | 運営責任者が引き取る。メールを読んだだけでは割当完了にしない |
| 案件担当 | 売り手／買い手双方の状況、次の行動、期限を更新し、成約または終了まで追う | 代行者に明示的に引き継ぐ。担当変更を履歴に残す |
| 審査担当 | 必要情報・掲載可否を確認し、公開／差し戻し理由を記録 | 案件担当へ不足と期限を渡す |
| 契約・請求担当 | 契約書送付、署名確認、請求書送付、入金確認を記録 | 未送付・未署名・期日超過を案件担当と共有 |
| 運営責任者 | 未割当・期限超過・長期停滞・失注理由を確認する | 対応方針や優先度を判断する |
| 売り手 | 機器情報、在庫、売却条件、契約・搬送の確認に回答する | 案件担当が催促・保留判断を行う |
| 買い手 | 希望条件、予算、導入時期、候補・契約への回答をする | 同上 |

一人が複数役を兼ねても構いません。ただし案件ごとの責任者は一人にし、「運営全体」「誰か」にしない運用にします。

## 3. 誰が・いつ・何をするか

下表は実装後の標準運用案です。現状はCRMと手動連絡を使って代替します。期限は営業日基準です。

| 発生条件 | 次に動く人／運営責任者 | 期限案 | 行うこと | 完了条件・次のタスク | 利用者への連絡 |
|---|---|---|---|---|---|
| 相談・審査提出の受付 | 受付当番 | 翌営業日12時まで | 重複、返信先、売り／買い、緊急性を確認し担当を決める | 担当＋初回連絡期限を保存 | 受付番号・受理内容・初回連絡目安を即時通知 |
| 担当決定 | 案件担当 | 受付から1営業日以内 | 相手へ初回連絡。目的と不足情報を確認 | ヒアリング完了、または不足と回答期限を記録 | 売り手には売却条件、買い手には購入条件の確認依頼 |
| 情報不足 | 売り手または買い手／案件担当 | 回答依頼から2営業日 | 必要項目を箇条書きで一度に依頼 | 回答で審査再開。未回答なら担当へ再確認タスク | 依頼の内容と回答期限。催促は同じ情報を繰り返し送らない |
| 情報が揃う | 審査担当／案件担当 | 1営業日以内 | 内容を確認し公開または理由付き差し戻し | 公開時に「相手探し」を作成 | 公開／修正依頼、次の対応予定 |
| 売りたいを公開 | 案件担当 | 公開後2営業日以内 | 買い希望から候補を探し、予算・時期・条件を照合 | 候補ごとの採用／見送り理由、打診相手と期限を保存 | 売り手へ探索状況と次回報告日 |
| 買いたいを公開 | 案件担当 | 公開後2営業日以内 | 在庫と売り手を探し、販売可能・価格・状態を確認 | 候補ごとの確認結果と提案予定を保存 | 買い手へ候補または探索状況と次回報告日 |
| 候補がない | 案件担当 | 初回探索後、以降5営業日ごと | 条件拡張、代替機種、探索継続／保留を相談 | 次回探索期限または再開日を保存 | 「候補なし」も報告。次回連絡日を伝える |
| 関心／提案が入る | 案件担当 | 1営業日以内 | 双方の意向と在庫を確認。既存コメントも読む | 仲介開始または見送り理由を保存 | 受付通知に加え、担当・次の確認内容を案内 |
| 仲介開始 | 案件担当 | 開始当日 | 価格、保守、付属品、費用負担、時期を整理 | 双方ごとの未確定条件・回答担当・期限を設定 | スレッドと次に回答する項目を案内 |
| 相手の回答待ち | 相手／案件担当 | 2営業日で初回確認、5営業日で再確認 | 回答の有無とメール不達を確認し、必要なら電話等に切替 | 回答で待ちタスクを完了し、次の作業を作成 | 上限2回の催促を仮案とし、以後は責任者が判断 |
| 条件合意・開示希望 | 案件担当 | 双方の確認後 | 取引条件と連絡先開示への双方の同意を別々に記録 | 証跡を添えて開示。契約手続きタスクへ | 開示通知。メールには相手の連絡先を含めない |
| 仲介契約の手続き | 契約担当／案件担当 | 契約条件確認から1営業日以内 | 売り手へ契約書を送り、署名を確認 | 送付先・送付日・書類版・署名証跡を保存 | 契約書確認依頼、署名期限、完了案内 |
| 売買契約の手続き | 契約担当／案件担当 | 仲介契約署名後 | 売買契約書を送り双方の署名を確認 | 署名証跡と確定金額を保存して成約 | 対象機器・契約書・期限を案内 |
| 成約 | 案件担当＋契約・請求担当 | 成約登録当日 | 投稿の在庫状態を更新、他の候補を整理し請求を用意 | 請求送付・入金確認・搬送・検収の各タスクを作成 | 成約通知。売り手には請求、買い手には今後の手順 |
| 請求・入金 | 請求担当 | 合意した支払期日に従う | 請求書送付と実入金を確認。期日超過は担当へ連絡 | 支払証跡・消込を保存 | 請求書、必要時の督促、入金確認。成約通知で代用しない |
| 搬送・検収 | 当事者／案件担当 | 合意した予定日に従う | 搬送・受領・動作確認、残課題を確認 | 売買の履行と未完了タスクを確認して終了 | 予定確認・受領確認。問題があれば個別対応 |
| 辞退・不成立・終了 | 案件担当 | 判明当日 | 理由、対象候補、再探索の要否を記録 | 候補のみ終了か、売却／購入希望全体の終了かを区別 | 相手へ結果と次の方針を案内。予定通知を停止 |

売り手の最低売却額や買い手の上限予算など、片側だけの交渉情報は内部メモまたは片側メッセージに残します。双方共有の条件表へ移すのは、共有してよい内容に限ります。

## 4. すぐに始められる運用

新機能が入るまでの暫定手順です。

1. 毎営業日9時・16時に `/admin` を確認し、未割当・次回予定なし・通知失敗から整理します。既存39件は外部の電話・メール履歴と照合し、実案件、完了案件、テスト受付を分けます。確認せずに一括完了しません。
2. 売りたい／買いたいのCRMを探索の主記録にし、担当・次の対応・期限を保存します。「候補を探す」ではなく「買い希望3件の予算を照合し、適合する2者へ打診する」など、完了が分かる書き方にします。
3. 関心／提案が来たらそのCRMにも同じ担当を入れ、元投稿のCRMに関連IDと進行先を記録します。仲介開始後はスレッドCRMを交渉の主記録にします。元投稿の在庫・募集管理は続けます。
4. 電話・メール・LINEで連絡したら、相手、実施日時、結果、次の対応を当日中に記録します。CRMの「メール」を選んでもメールは送られない点を共有します。
5. 契約書・請求書は既存の実際の送付手段で送り、送付・署名・入金の証跡の保管先を記録します。「sent」表示だけで送付済みと判断しません。
6. 成約した投稿は運営が掲載状態を確認し、既存の安全な管理手段で公開を止めます。現行画面に停止導線がないため、権限のある技術担当への作業依頼を明示的に残します。数量が残る場合は残数と募集継続の判断を記録します。

保留も期限なしにしません。再開条件・再確認日を残します。担当不在なら、責任者が代行を割り当てます。

## 5. 管理画面の改善案

### 今日の対応

最初に「自分の作業」を表示し、未割当・期限超過・期限なし・通知失敗・回答待ち・本日分を別々に切り替えます。期限未設定を、期限超過0件の裏に隠さない表示にします。

各行には、案件名、売り／買い、段階、担当、次に動く人、次の対応、期限、最終連絡、待っている理由を並べます。「連絡する」「候補を確認」「署名を確認」など、その段階で必要な操作へ直接進めます。

### 案件詳細

売り手と買い手の連絡先・確認条件・担当を左右に分け、その下に受付から契約までの関連記録を時系列で表示します。公開状態とは別に、探索中・提案中・条件調整中などの商談段階を表示します。

候補ごとに、適合理由、未確認条件、在庫確認日、打診日、返答期限、結果、見送り理由を保存します。メール履歴には、送信依頼・プロバイダー受付・配達確認・失敗を区別して表示します。担当変更とタスクの引継ぎも同じ履歴に残します。

### 操作の出口

公開、仲介開始、条件合意、契約送付、成約などの操作を終えると、次のタスクを自動作成します。担当・期限のない状態で工程を進めない設計にします。担当が入力するのは、その案件だけの例外や具体的な確認内容です。

## 6. データと処理の設計案

既存の投稿・アプローチ・契約を置き換える前に、関連を補う追加マイグレーションで導入します。この文書ではDB変更を適用していません。

| データ | 持たせたい情報 | 既存との関係 |
|---|---|---|
| 取引案件 `opportunities` | 起点、段階、責任者、主窓口、最終進展日、保留／終了理由 | 相談・売り希望・買い希望を関連づける。原本を残す |
| 関連 `opportunity_links` | 相談、投稿、アプローチ、スレッド、仲介契約、売買契約、請求ID | 「同じ組織だから同じ商談」と推定せず、明示的に結ぶ |
| 候補 `match_candidates` | 双方、対象投稿、適合・不適合理由、在庫確認、提案・回答状態 | 一つの希望に複数候補を持てる。候補の辞退で希望全体を閉じない |
| タスク `operation_tasks` | 実行担当、運営責任者、対象側、作業種別、期限、状態、完了証跡、発生イベント | 一案件に複数タスク。CRMの一つの `next_action` では契約と搬送等を並行管理しにくい |
| 配信 `notification_outbox` | イベント、宛先、テンプレート版、状態、試行回数、次回試行、プロバイダーID、エラー | DB更新と通知予約を同一トランザクションにする |
| 同意・契約証跡 | 対象文書の版、同意者、確認者、日時、手段、記録先 | 既存の開示記録を維持。開示同意・仲介契約署名・売買契約署名を混同しない |

処理上の要件：

- 同じイベントからタスクやメールを二重作成しない一意キーを持たせます。イベントID・宛先・テンプレート版で制御します。
- DB保存失敗時は通知を送らず、メール失敗時は保存済みの案件を消さずに再送します。
- 「送信受付」と「配達完了」は別に記録します。Webhookは署名を検証し、重複イベントにも対応します。
- 返信、成約、辞退、保留、担当変更時に古い催促を停止または更新します。送信直前にも状態を確認します。
- 主担当・代行者・当事者ごとの窓口を明示し、「最初に登録した会員」への固定送信をやめます。
- 通知やタスクの重複防止、バッチの同時実行制御、休日計算、再送上限をテストします。
- 成約時はDBで関連状態を一括更新します。対象投稿の残数量、他の進行中候補、検収前の会話継続を考慮します。

## 7. 実装の優先順位と受入条件

| 順番 | 実装 | 受入条件 |
|---|---|---|
| 1 | 公開メールのURL修正、相談者への受付通知、通知失敗の可視化 | 実メールから対象へ到達。相談に受付番号。失敗だけ再送できる |
| 2 | 公開・受付・関心／提案・仲介開始で担当と次回タスクを作成 | 新規案件に担当なし・期限なしが残らない。例外には理由と責任者がある |
| 3 | 統一案件と双方の窓口、相談→投稿、Q&A→仲介の引継ぎ | 同じ内容を二重入力せず、履歴を追える。第三者には見えない |
| 4 | 運営の候補探索・打診・返答期限の管理 | 双方向で候補作成から返答・見送りまで記録できる。必須条件違反を候補から除く |
| 5 | 成約と投稿状態の同期、契約送付／署名の証跡、請求・搬送・検収タスク | 成約済み機器に新規申込が入らない。送付記録なしを送付済みと扱わない |
| 6 | 期限通知・進捗報告・催促の自動化 | 返信や終了で停止。担当変更を反映。再試行しても二重送信しない |
| 7 | 事業者確認画面、宛先管理、処理速度・失注理由の集計 | 消耗品提出の確認依頼を運営画面で完結。数字の定義が統一される |

段階1〜2で取りこぼしを減らし、段階3〜5で取引の連続性を整えます。催促の大量自動化は、担当・状態・期限・宛先が正しく保存できるようになってから導入します。実顧客への一斉通知や過去案件の一括更新は本書の作成では実施していません。

## 8. 運営が見る指標

| 指標 | 定義 |
|---|---|
| 未割当件数 | 進行中で運営責任者がいない案件数 |
| 期限なし件数 | 進行中で次のタスクまたは期限がない案件数 |
| 初回対応時間 | 受付から最初の人による連絡まで。自動受付メールを除く |
| 期限遵守率 | 期限到来タスクのうち期限内に完了した割合 |
| 初回提案までの日数 | 条件確定から最初の具体的な候補提案まで |
| 返答待ち滞留 | 買い手・売り手・運営別に、未回答の営業日数を集計 |
| マッチング率 | 条件確認済み希望のうち、双方が具体的な候補との交渉に進んだ割合 |
| 成約率 | 仲介開始した候補のうち売買契約成立まで進んだ割合。単なる連絡先開示を含めない |
| 通知失敗率 | 配信試行のうち失敗・バウンスした割合。API受付と配達を分ける |
| 失注理由 | 価格・機種・時期・状態・保守・搬送・返答なし等。希望全体か候補単位かを区別 |

営業日、初回対応の定義、マッチングの完了地点を固定してから数値を比較します。

## 9. 実装前に確定する運用条件

初期案はこの文書のとおりに置けますが、利用者へ約束する前に、受付当番と代行者、営業時間と休日、初回対応の目安、催促回数、契約・請求の実際の送付手段を確定します。特に「運営が相手を探す」を標準サービスにする場合は、初回探索と定期進捗報告を担当の作業量に含めます。
