# 利用者画面の見直し（2026-09-18）

## 方針と参考

remove-ai-web-style / natural-japanese-writing の方針に沿い、クリニックマッチの色と既存機能を保ちながら、売却・購入の目的と次の操作が読み取れる構成に変更した。
Inspo の Brethren Design Co. のショップ画面（https://www.brethrendesignco.com/shop）を参照し、カテゴリと一覧の階層、区切り線の使い方を参考にした。書体や配色は採用していない。

## 変更

- トップ：売却相談と在庫検索を分離。スマートフォンでは成約事例より先に検索を配置。大きな統計カード・装飾バッジを整理し、成約一覧は機器名から詳細へ移動できるようにした。
- 一覧・詳細などの共通部品：角丸と影を抑え、ボタン・入力欄・フォーカス表示を統一。写真なしカードの既存処理は維持。
- 会員登録：ログイン情報、事業者情報、利用時の表示・目的に区切った。法人・個人の条件付き入力とバリデーションは維持。
- マイページ：出品・購入希望の登録、メッセージ、送った関心・提案、契約を明確に分けた。投稿タイトルから状態に応じた画面へ移動でき、保管済み投稿を概要から除外。取得エラーを空データと区別した。
- 売りたい・買いたい一覧：審査への案内、空状態・取得エラー、公開ページへのリンクを追加。カテゴリの内部識別子は日本語名で表示。
- 自動入荷通知が未実装であるため、トップ・案件一覧の即時通知の案内を購入希望登録・相談の案内へ変更。実際の関心・提案メールの案内は維持。

## 検証

- production build 成功。
- 変更した Astro ファイルの ESLint 成功。
- workflow / trade テスト成功（DB フローと通知宛先を含む。外部メール送信なし）。
- Astro check は既存の16件のエラーが残る。対象は Sanity、Content/FAQs、home-page.ts、ブログの既存型エラーで、今回変更箇所の追加エラーなし。
- ローカルでトップの PC / 390px 表示、検索配置、案件一覧の横はみ出し、登録の法人・個人切り替えと必須・無効状態を確認。
- ローカルには本番認証設定がないため、認証済み画面の実データ確認は本番反映後に読み取りのみで行う。登録・投稿・メール送信など実データ変更はこの UI 確認では行わない。
