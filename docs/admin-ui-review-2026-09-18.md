# 運営画面のUI見直し

2026-09-18。取引フロー監査で分かった「担当・期限・次の対応が追いにくい」という課題を対象に実施。

## 使用したスキルと参考

- `remove-ai-web-style`：均等な装飾カード、過剰な角丸、用途に合わない見出しを避け、業務上の比較と操作を優先。
- Inspoで [Amie](https://amie.so) と [Trello](https://trello.com) の公開ページと、掲載された製品UIを確認。Amieのナビゲーションと作業領域の分離、Trelloの受信した仕事を一覧で扱う考え方を参考にした。これらは管理画面を直接操作した調査ではない。
- 配色と書体のブランドは既存のクリニックマッチを継承。外部サービスのヒーローや装飾はコピーしていない。

## 変更

- 全運営ページ共通：専用ヘッダー、左側の業務メニュー、作業領域。メニューを「対応を進める」「取引を進める」「管理」に分け、現在地を表示。
- 公開サイトの販促用フッターやモバイル下部CTAに代えて、公開サイト・マイページへのリンクを配置。
- 大きな見出し、丸いメニューボタン、カードの繰り返しを抑え、罫線・文字の強弱・余白で情報を整理。
- 案件一覧：案件・相手、次の対応、担当・期限、状態を並べる。内部IDよりも案件名と作業を先に表示。連絡先と履歴未登録の注意は維持。
- 期限超過・今日が期限・担当未割当・次回予定なしをクリックできる絞り込みに変更。下書き・完了・保管済みを要対応集計に含めない。絞り込み解除と空状態を用意。
- モバイル：メニューを開閉式にし、表の行を縦に再配置。案件名・次の対応・担当と期限を横スクロールなしで読む。
- 案件詳細：担当・次の対応・期限を上部に集約。次回予定と今回の対応記録を区切る。メールの記録が実送信を意味しない説明を維持。
- 関心・提案、メッセージ一覧：0件時の案内と次の導線を追加。取得失敗と0件を区別。

## 検証

- 架空データを使い、PC 1280px／スマートフォン390pxの表示を確認。390pxでページの横はみ出しなし。表示用の一時ルートは削除済み。
- 要対応の絞り込みと他のフィルターとの組み合わせを回帰テストに追加。
- ワークフロー回帰テスト、変更ソースのESLint、ビルドを実施。
- 全体のAstroチェックには既存のSanity・共通ウィジェット等の16エラーが残る。今回の変更ファイルに新規エラーなし。

担当の自動割当、タスクの自動作成、メールの再送などは、別紙の運営フォロー設計に記載した今後の実装項目。今回のUIに未実装の機能が使えるような表示は追加していない。
